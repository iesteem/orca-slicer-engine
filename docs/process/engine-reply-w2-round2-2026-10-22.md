## 答问题二：浅埋 -13.5 失败 / 深埋 -40 成功 = **设计语义 + fixture 精度，不是深度阈值 bug**

**关键事实：该 3mf 并非"完全埋入"。**

- 网格 z ∈ [−13.5, +13.5]，而 3mf 里 instance **z = −13.45**（≠ −13.5）→ 世界 bbox = −26.95 ～ **+0.05mm**，顶部高出床面 0.05mm。
- 引擎单件抬起条件（`src/SliceEngine.cpp:2126`）：`min_z ≥ −0.001 || max_z < 0`。此例 max_z = +0.05 ≥ 0 → 判为"**跨床 = 作者有意部分沉床**，保留原样"→ 发 `OBJECT_INTENTIONALLY_BELOW_BED`（与你们 JSON 里消息中的 bbox 数字互为印证）。
- 保留后床面以上只剩 0.05mm，低于首层层高 → 引擎日志实证 **"No layers were detected"** → `SLICING_FATAL_ERROR` exit 4。
- −40mm 变体 max_z = −26.5 < 0，真全埋 → 抬起 53.5mm → `OBJECT_BELOW_BED_ADJUSTED` exit 0。

**定性：** V05 的"抬起"语义只适用**真全埋**（max_z < 0）；跨床对象保留原样是明确设计（消息文案即如此）。本地 2.2.0 复切复现，与 02.01.06 行为一致，非版本回归。**建议**：fixture 的 instance z 改为 ≤ −13.55（留余量）即可落入"抬起"分支。

## 答问题三：两路径混用检测未触发 = **两个不同的根因**

### A. 全局-支撑筏层界面 —— **送检原件复核：实为 ranges 构造，已随 B 修复一并拦截**

收到回执原件静态 diff：两条送检 3mf **配置 100% 相同**（唯一差异 `identify_id`），`support_interface_filament="1"`（PLA 低温槽）——**并非 README 所述"挂高温槽"构造**，高温 ABS 仅由 layer_config_ranges 引用（range 0-2：extruder=3 + wall_filament=3）。即"全局-支撑筏层界面"文件实际也是高度范围（B 路径）构造。**实测（修复版二进制）：两条原件均 RC=6 + `FILAMENT_TEMP_MIXING`**，与文件名预期"切片失败"及 V05 规格一致。

"支撑界面键挂高温槽"的构造**未落到送检文件里**（同文件 sparse/solid_infill_filament=2 都持久化了，support 键却为 1）——请检查导出流程后重新出件。该路径机制引擎侧已单独实证（重构实验）：全局 support 键挂高温槽时，官方名/拷贝两分支的工艺替换都会把该键清回官方值，检测器看到的配置本无混用——属 **P-30 wholesale 替换家族**，是否豁免 support/wipe_tower 耗材键待产品决策，引擎侧不单方面改。

### B. 自定义层高（高度范围换槽）—— 真收集缺口（与桌面同源）—— **已修复（2026-10-22，判例 P-33）**

`check_filament_temp_mixing`（`src/SliceEngine.cpp:3306`）的槽位收集器不读 `layer_config_ranges`。本地实证：高度范围挂 ABS 槽、基础色 PLA，**gcode 实际使用了 T0+T2 双槽（真高低温混用）**，仍 exit 0 无告警。桌面端收集器逐行同构（Plater.cpp:22343）**同样漏**——即你们提到的 2.2.0 报告 issue#5 挂起族。

## 答问题四：回退类克重偏差 —— **−6.1% = 密度回退的精确算术；+4.2% 本地不可复现**

源 3mf 密度：Matte 槽（1、4）= **1.32**、Metal 槽（2）= 1.25、拷贝槽（3）= 1.24；引擎回退后统一按 Generic PLA **1.24** 计重。本地 2.2.0 实测：
