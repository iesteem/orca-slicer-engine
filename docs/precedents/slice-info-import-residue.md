# P-32: slice_info 导入残留叠加——旧引擎产物污染源 3MF + parse 不清空（已修复）

**状态：** 2026-10-21 修复（W2 批次发现四定性升级驱动）

## 现象（W2 发现四，QA 原始观察）

5215 用例（擦除矩阵 3×3 vs 4 槽）引擎产物 `Metadata/slice_info.config` 每盘
filament 条目为 `[3,4,6,7,8,1,3,4]` 八条：

- 虚拟槽 6/7/8 **携带实际克重**（14.46/12.45/10.01g）
- 物理槽 id 3/4 **重复出现**（值不同）
- 条目求和 109.06g ≠ 同文件 plate `weight` 元数据 52.97g（2 倍）
- 引擎 JSON 侧干净（[1,3,4]，Σ=weight）——两份账对不上

## 根因（两层叠加）

1. **源 3MF 自带污染**（决定性证据：源 `Metadata/slice_info.config` 残留条目
   `[3:8.46, 4:10.71, 6:14.46, 7:12.45, 8:10.01, …]` 与引擎输出前 5 条**逐值
   相同**）。源是用例制作链用**旧版引擎产物**回存出来的——虚拟槽 6/7/8 是
   flush-matrix 规整时代（fe5c61c 前/初期）旧版写出的统计形态。
2. **读侧残留不清空**：3MF 导入把内嵌 slice_info 读进
   `PlateData::slice_filaments_info`（bbs_3mf.cpp 读侧），而
   `parse_filament_info`（bbs_3mf.cpp:655）**只 push 不 clear**——导出统计 =
   导入残留 5 条 + 本次切片 3 条 {1,3,4} 恰为观察到的 8 条与 109.06g。
   引擎本次切片的统计本身是干净的（虚拟槽不在其中）。

## 修复（引擎侧，不动 fork 共享代码）

`populate_plate_data_for_export`（SliceEngine.cpp）在
`pd->parse_filament_info(...)` 前 `pd->slice_filaments_info.clear()`——
**导出统计只描述本次切片，永不继承导入**。

## 验证（2026-10-21 实测）

5215 三盘全部输出 `[1,3,4]`，Σ条目 == plate weight（52.71/68.18/76.39 三盘
自洽 ✓）；克重较修复前微变（35.15 vs 35.30 等）是因为叠加消除后 density 取
本盘切片真值。

## 给 QA 的口径（W2 发现四答复）

- json `plates[].filaments` 与 slice_info 修复后**同源同口径**：真实物理槽
  去重集合，**不含** flush-matrix 虚拟槽；重复 id 条目不存在
- 旧观察到的 `[1,3,3,4,4,6,7,8]`（02.01.06 产物）= 本判例两层叠加，02.01.06
  同样存在（QA 可用旧版复现确认）
- **QA 用例制作链注意**：不要用旧引擎产物 gcode.3mf 改后缀当源 3MF——残留
  slice_info 会被读入并（修复前）叠加进产物
