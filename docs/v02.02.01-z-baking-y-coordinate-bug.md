# Z-Baking Y 坐标越界 Bug 分析报告

**版本**: v02.02.01+ (2026-06-29)  
**严重程度**: P0 — 多挤出机旋转模型切片输出坐标越界，打印时间膨胀 60 倍  
**影响范围**: 含 ~90° 旋转 + 非零 Z 偏移的多挤出机（多色）模型  

---

## 1. 问题现象

White Eagle 4 色模型切片后，G-code 中 Y 坐标异常：

```
; 正常坐标（prime tower 区域）：
G1 X43.75 Y245.35 Z.6          ← Y=245，床范围内

; 异常坐标（模型打印区域）：
G1 X320.96 Y211001.98 Z.6      ← Y=211,002mm = 211 米
```

| 指标 | 损坏值 | 正常值 |
|------|--------|--------|
| 挤出 Y 范围 | [0, 211,017] mm | [95.80, 248.85] mm |
| 预估打印时间 | 11 天 9 小时 (274h) | 4 小时 32 分 |
| G1 总行数 | 1,956,003 | 974,696 |
| Y 偏移量 | ~210,853 mm (~211 m) | 0 |

每次工具切换的旅行移动覆盖 ~211 米，824 次换料累积为荒谬的打印时间。

---

## 2. 根因分析

### 2.1 Z-Baking 机制

Z-baking 的目的是补偿 Slic3r 库中 `Print::apply()` 对实例 Z 平移的归零行为。当模型实例有非零 Z 偏移时（例如从底板上抬升），Z-baking 将实例 Z 偏移移入体积（volume）的 Z 偏移中：

```
z_adjustment = inst_offset.z() / z_scale
vol_offset.z += z_adjustment
inst_offset.z  = 0
```

其中 `z_scale` 是从实例变换矩阵的 `(2,2)` 元素（m22），表示物体的局部 Z 轴对世界 Z 轴的贡献。

### 2.2 White Eagle 模型的特殊变换

White Eagle 的 3MF item transform 包含：

```
10x 均匀缩放 + ~90° 绕 X 轴旋转 + 平移 (135.5, 136, 69.89)
```

变换矩阵的关键元素：

```
m12 =  9.99999518   ← 物体局部 Z 映射到世界 Y（主导项）
m22 = -0.00331471   ← 物体局部 Z 映射到世界 Z（接近零！）
```

由于 ~90° 旋转，`m22`（z_scale）接近零（-3.3×10⁻³），而 Z 列范数（z_col_norm）≈ 10（因为其他分量 m02、m12 约为 10）。

### 2.3 数值推导

```
z_scale       = m22 = -3.3147×10⁻³
z_col_norm    ≈ 10.0
比值          = |z_scale| / z_col_norm = 3.3×10⁻⁴

inst_offset.z = 69.89 mm
z_adjustment  = 69.89 / 3.3×10⁻³ ≈ 21,085 mm    ← 21 米！
```

世界 Y 偏移 = m12 × z_adjustment ≈ 10 × 21,085 = **210,853 mm ≈ 211 米**

### 2.4 门卫阈值失效

PlateProcessor.cpp:710 的跳过条件：

```cpp
if (std::abs(z_scale) / z_col_norm < 1e-6) continue;
```

```
实际比值：3.3×10⁻⁴
阈值：    1.0×10⁻⁶
结论：    3.3×10⁻⁴ > 1.0×10⁻⁶  →  未跳过 → Z-baking 执行 → 坐标损坏
```

阈值 `1e-6` 只能捕获比值 < 0.000001 的情况（旋转角度 > 89.99994°）。White Eagle 的比值 3.3×10⁻⁴ 对应的旋转角度约为 89.98°，刚好卡在阈值的缝隙中。

---

## 3. 为什么其他模型没有触发？

Z-baking 坐标损坏需**三个条件同时满足**：

```
条件 1: inst_offset.z() ≠ 0           ← 模型被抬离底板
   AND
条件 2: z_scale (m22) 接近零           ← 旋转接近 90°
   AND
条件 3: 比值落在 [1e-6, 1e-2] 缝隙    ← 旧阈值未捕获
```

### 典型模型分类

| 模型类型 | 条件 1 | 条件 2 | 条件 3 | 结果 |
|---------|:------:|:------:|:------:|------|
| 平放在底板上（绝大多数） | ❌ Z=0 | — | — | 行 693 `continue` 跳过 |
| 抬升但无旋转 | ✅ | ❌ m22≈1 | ❌ 比值≈1 | z_adjustment ≈ offset_z，正常 |
| 旋转 45° + 抬升 | ✅ | ❌ m22≈0.7 | ❌ 比值≈0.7 | z_adjustment ≈ offset_z/0.7，合理 |
| 旋转 89.999°+ | ✅ | ✅ | ❌ <1e-6 | 旧阈值正确捕获 |
| **旋转 ~89.98° + 抬升** | ✅ | ✅ | ✅ **3.3e-4** | **触发 bug** |

### 已知受影响模型

| 模型 | 偏移倍数 | 原因 |
|------|---------|------|
| White Eagle (Rocket Luo) | ~1000x | m22 = -3.3e-3, z_adj ≈ 21,085 mm |
| Duck (Rocket Luo) | ~10x | 旋转角度略小，m22 绝对值更大 |

Duck 偏移较小是因为其旋转角度不如 White Eagle 接近精确 90°，`|m22|` 更大 → `z_adjustment` 更小 → Y 偏移仅 ~1,830mm。

### 为什么是 Rocket Luo 的模型

Rocket Luo 的设计风格包含两个特征：
1. **多色打印**（4 色）→ 需要多挤出机 → wipe tower 和频繁工具切换
2. **非标准模型朝向** → 3MF 中包含 ~90° 旋转 + 缩放的 item transform

大多数模型平放在底板上（Z=0），或仅做平移（无旋转），不会同时满足三个条件。

## 4. 解决方案

### 4.1 修改内容

**一行改动**，在活跃代码路径 `PlateProcessor.cpp:710`：

```diff
- if (std::abs(z_scale) / z_col_norm < 1e-6) continue;
+ if (std::abs(z_scale) / z_col_norm < 1e-2) continue;
```

### 4.2 阈值选择依据

比值 `|z_scale| / z_col_norm` 的几何意义是 **cos(物体Z轴与世界Z轴的夹角)**：

| 旋转角度 | cos(θ) | 1e-2 阈值 | 1e-6 阈值 |
|---------|--------|:--------:|:--------:|
| 0° (直立) | 1.0 | 通过 | 通过 |
| 45° | 0.707 | 通过 | 通过 |
| 84° | 0.105 | 通过 | 通过 |
| 89.4° | 0.010 | **跳过** | 通过 |
| 89.98° (White Eagle) | 3.3e-4 | **跳过** | **未跳过 ❌** |
| 89.99994° | 1.0e-6 | **跳过** | **跳过** |

`1e-2` 对应 `cos(θ) < 0.01` → `θ > 89.4°`。当角度超过 89.4° 时，物体局部 Z 轴只有不到 1% 映射到世界 Z，Z-baking 已无意义且会引入巨大误差。

### 4.3 同步死代码清理

SliceEngine.cpp 中存在同一段 Z-baking 代码，已于 commit `0ec93d4` 修复但经重构（`1fe9058`）后成为死代码。本次一并删除，消除维护隐患：

## 6. 风险评估

### 6.1 已缓解的风险

| 风险 | 评估 |
|------|------|
| 阈值过宽导致合法 Z-baking 被跳过 | **低风险**。`1e-2` 只跳过角度 > 89.4° 的旋转，此角度下 Z-baking 本身就是错误的——物体 Z 轴与世界 Z 几乎正交，Z 偏移应通过其他分量（X/Y）补偿而非丢弃 |
| 影响正常抬升模型 | **无影响**。直立模型 m22 ≈ 1，比值 ≈ 1，远大于 1e-2 |
| 性能退化 | **无**。只增加一次浮点除法比较 |

### 6.2 残余风险

| 风险 | 评估 | 缓解措施 |
|------|------|---------|
| 阈值 1e-2 可能对 84°–89.4° 旋转的模型过于保守 | **极低**。此角度范围下物体 Z 轴仅 1–10% 映射到世界 Z，跳过 Z-baking 可能导致 Z 定位偏差，但偏差量与旋转角度的 sin 分量成正比（<10%），远小于不跳过的 Y 偏移风险 | 如需支持此类边界情况，可改为检测 `\|z_adjustment\| > 1000.0` |
| 死代码删除可能遗漏外部调用者 | **已排除**。通过 grep 确认 9 个方法在所有源文件中无外部引用 | — |
| libslic3r.so 内部可能存在类似阈值问题 | **无法修复**。库为预编译，仅能通过 wrapper 层防御 | 关注 OrcaSlicer 上游修复 |

### 6.3 建议的后续工作

1. **上游汇报**：向 OrcaSlicer 提交此 bug 的修复，确保桌面版也受益
2. **测试用例**：添加 90° 旋转 + Z 偏移模型的回归测试
3. **监控**：线上监控多色模型的打印时间估算，异常高值（>24h 且耗材 <200g）自动告警

### 5.4 Duck 未修复分析

Duck 的实例变换与 White Eagle 类似（~10x 缩放 + 旋转），但旋转角度较小：

```
Duck item 0 transform:
  m00=9.997, m01=-0.238, m02=0.015, tx=99.927
  m10=0.010, m11=-0.208, m12=-9.998, ty=113.921
  m20=0.238, m21=9.995, m22=-0.208, tz=35.849

z_scale (m22)    = -0.2079
z_col_norm       = 10.0
ratio             = 0.0208
inst_offset.z()  = 35.85 mm
z_adjustment     = 35.85 / -0.2079 ≈ -172.4 mm
world ΔY         = m12 × z_adjustment = -9.998 × -172.4 ≈ 1,724 mm
```

**为什么 1e-2 阈值未能捕获：**

```
实际比值: 0.0208
阈值:     0.0100
结论:     0.0208 > 0.0100 → 未跳过 → Z-baking 执行 → 1,724 mm Y 偏移
```

`1e-2` 对应 `cos(θ) < 0.01` → `θ > 89.4°`。Duck 的比值 0.0208 对应 `cos⁻¹(0.0208) ≈ 88.8°`，恰好在此之下。

阈值与捕获范围的对比：

| 旋转角度 θ | cos(θ) | White Eagle (θ≈89.98°) | Duck (θ≈88.8°) |
|-----------|--------|:---------------------:|:--------------:|
| 87.1° | 0.05 | 跳过 ✅ | 跳过 ✅ |
| 88.8° | 0.021 | 跳过 ✅ | **未跳过 ❌** |
| 89.4° | 0.01 | 跳过 ✅ | 未跳过 |
| 89.98° | 3.3e-4 | 跳过 ✅ | — |

Duck 的 1,724 mm 偏移不会导致极端的打印时间估计（~10 倍而非 ~1000 倍），因为相对增量移动仍然保持正确的比例。但它确实产生了一个位于床外的打印对象。

## 8. 备选方案：世界空间位移检查

### 8.1 动机

基于比率的阈值 `|z_scale| / z_col_norm` 面临一个根本性矛盾：

- **阈值过紧**（如 `1e-2`）：遗漏 Duck 类模型（旋转 88°–89.4°）
- **阈值过松**（如 `5e-2`）：对合法模型过于保守——在 84° 旋转时跳过 Z-baking 可能导致 Z 定位偏差

此外，基于比率的防护是间接的——它通过几何角度推断风险，而非直接衡量损坏程度。

### 8.2 方案：直接检测世界空间位移

直接计算 Z-baking 产生的**世界空间位移量**，仅当位移超过安全阈值时跳过：

```cpp
// 计算 Z-baking 的世界空间位移向量
// z_adjustment 是体积 Z 偏移的变化量（局部空间）
// 世界位移 = 实例变换的 Z 列 × z_adjustment
Eigen::Vector3d z_adjustment_world = 
    inst->get_transformation().get_matrix().matrix().block<3,1>(0, 2) * z_adjustment;
double world_displacement = z_adjustment_world.norm();
if (world_displacement > 100.0) continue;  // 位移 > 100mm 时跳过
```

### 8.3 数值验证

| 模型 | z_adjustment | Z 列范数 | 世界位移 | 150mm 阈值 |
|------|-------------|---------|----------|:---------:|
| **White Eagle** | -21,085 mm | 10 | **210,850 mm** | 跳过 ✅ |
| **Duck** | -172 mm | 10 | **1,724 mm** | 跳过 ✅ |
| 直立 45° + 抬升 20mm | 28 mm | 1 | 28 mm | 放行 ✅ |
| 平放（Z=0） | 0 | — | 0 | 放行 ✅ |
| 无旋转 + Z=100mm | 100 mm | 1 | 100 mm | 放行 ✅ |

### 8.4 优势

1. **直接性**：直接衡量 bug 的症状（世界坐标越界），而非通过几何中间量推断
2. **覆盖完整**：同时捕获 White Eagle（210,850mm）和 Duck（1,724mm），对任何产生 >100mm 世界位移的 Z-baking 都触发保护
3. **假阳性率低**：合法 Z-baking 的世界位移量级为 `|inst_offset.z| × scale`（通常 < 100mm）。100mm 阈值留有充足余量
4. **阈值直观**：100mm = 典型打印机床深度的一半，越界行为明确

### 8.5 实现

对 `PlateProcessor.cpp:710` 的修改方案：

```diff
-        // The ratio |z_scale| / z_col_norm is cos(angle) between the object's Z
-        // axis and world Z.  When cos(angle) < 1e-2 (angle > ~89.4 degrees),
-        // less than 1% of the object-local Z maps to world Z — Z-baking would
-        // inject a huge world-Y (or world-X) displacement proportional to the
-        // reciprocal of this tiny cosine (e.g. 3.3e-4 reciprocal ≈ 3,000×).
-        //
-        // Concrete case: White Eagle model rotated ~90° around X with
-        // m22 = -3.3e-3, z_col_norm = 10 → ratio = 3.3e-4.
-        // z_adjustment = 69.89 / 3.3e-3 ≈ 21,085 mm, mapped to world Y via
-        // m12 ≈ 10 → +210,853 mm Y shift — 211 meters off the bed.
-        // This causes every tool-change travel to cover ~211 m, inflating
-        // estimated print time to ~274 hours for an 824-change 4-color print.
+        // Calculate the world-space displacement caused by Z-baking.
+        // When the object is rotated, the Z-baking adjustment in local Z
+        // gets mapped to world X/Y through the instance transform's Z column.
+        // Guard: skip Z-baking if the resulting world displacement exceeds
+        // 100 mm (half the typical bed depth). This catches two failure modes:
+        //
+        //   1. Near-90° rotation (White Eagle): m22 ≈ -3.3e-3, z_adj ≈ 21,085 mm
+        //      → world displacement ≈ 210,853 mm
+        //   2. Moderate rotation (Duck): m22 ≈ -0.208, z_adj ≈ -172 mm
+        //      → world displacement ≈ 1,724 mm
+        //
+        // Both produce world-space shifts far outside the printable bed.
+        // For legitimate Z-baking (upright or small tilt), the displacement
+        // is on the order of |inst_offset.z| × |scale|, typically < 100 mm.
         Eigen::Vector3d z_col = inst->get_transformation().get_matrix().matrix().block<3,1>(0, 2);
         double z_col_norm = z_col.norm();
         double z_scale = inst->get_transformation().get_matrix()(2, 2);
         if (std::abs(z_col_norm) < 1e-9) continue;
-        if (std::abs(z_scale) / z_col_norm < 1e-2) continue;
         if (std::abs(z_scale) < 1e-9) continue;
         double z_adjustment = inst_offset.z() / z_scale;
+        Eigen::Vector3d z_adjustment_world = z_col * z_adjustment;
+        double world_displacement = z_adjustment_world.norm();
+        if (world_displacement > 150.0) continue;
```

### 8.6 风险评估

| 风险 | 评估 |
|------|------|
| 阈值 100mm 对合法模型太紧 | **低风险**。合法 Z-baking 的世界位移 ≈ `inst_offset.z × scale`。对于 U1（270mm 床），Z 偏移通常 < 80mm，缩放 < 2×，位移 < 160mm。100mm 可覆盖大多数情况；如遇边界案例可调至 150mm |
| 放行 <100mm 的损坏 Z-baking | **极低**。要产生 <100mm 世界位移同时损坏坐标，需要 `z_adjustment` 很小但 Z 列有显著的非 Z 分量——这是一个矛盾 |
| 与旧阈值相比的假阴性 | **无**。世界位移 >100mm 的模型也满足旧比率检查的条件；世界位移 <100mm 但比率 <1e-6 的情况不存在 |

### 8.7 决策建议

| 方案 | 捕获 White Eagle | 捕获 Duck | 假阳性风险 | 代码改动量 |
|------|:---:|:---:|:---:|------|
| A: ratio < 1e-2（当前） | ✅ | ❌ | 低 | 已完成 |

**建议方案 C**：世界空间位移检查，最终阈值选定 **150mm**（详见第 9 节交叉分析）。该方案直接衡量 bug 的症状（床外位移），同时允许正常情况无中断通过。阈值直观，且假阳性率最低。

#### 9.3.1 边界情况：60° 旋转 + Z=50mm

