# Orca Cloud Slice Engine 技术方案

> **版本**: v02.01.11 | **日期**: 2026-06-15 | **仓库**: orca-slice-engine

---

## 一、概述

云切片引擎是一个无头（headless）3MF 切片服务，基于 OrcaSlicer 的 libslic3r 核心库构建。设计目标为在 Kubernetes 集群中以 Pod 形式运行，接收 3MF 模型文件，输出 G-code 或 gcode.3mf 打包结果。

### 核心特性

- **双入口设计**：C++ 静态二进制（Linux）和 C API 共享库（Windows/Linux）共用同一管线
- **预设安全策略**：强制替换/验证打印机和耗材预设为官方 Snapmaker 预设，防止 RCE
- **全量问题收集**：所有错误、警告、提示通过结构化 Issue 体系汇总到 JSON 输出
- **复杂度预评估**：独立 Python 工具链，基于面片数和层数的二维评分预测耗时和 OOM 风险
- **TBB 线程控制**：支持通过 CLI 参数限制并行核心数，避免资源耗尽

## 三、核心管线详解

### 3.1 配置分层（7 层叠加）

每一层在前一层基础上叠加或替换配置项，`nil` 值从下层继承：

| 层 | 阶段 | 说明 |
|----|------|------|
| 1 | `FullPrintConfig::defaults()` | 系统级默认值，覆盖所有配置键 |
| 2 | `load_3mf()` | 从 3MF 文件加载项目配置和嵌入预设 |
| 3 | `load_system_presets()` | 加载 Snapmaker + OrcaFilamentLibrary 系统预设 |
| 4 | `validate_printer_official()` | 可能替换 `printer_settings_id`，从官方预设填充 nil |
| 5 | `apply_printer_preset_config()` | 从系统打印机预设填充剩余 nil 键 |
| 6 | `validate_filament_official()` | 可能替换 `filament_settings_id`，从官方耗材填充 nil |
| 7 | Per-plate `apply_model()` | 逐板应用特定配置覆盖 |

### 3.2 管线阶段

```
Stage 1: 加载验证
  load_3mf → validate_config → load_system_presets → validate_presets
  → validate_printer_official → apply_printer_preset_config
  → validate_filament_official → validate_printer_model → validate_input

Stage 2: 逐板处理 (per-plate loop)
  filter_instances → run_build_volume_check → apply_model
  → run_validation → run_slicing → export_gcode → run_postprocessing

Stage 3: 输出打包
  package_output → build_statistics → output_slice_statistics
```

### 3.3 预设安全机制

默认强制替换策略：

```
用户 3MF 中的 printer_settings_id
    │
    ▼
┌─────────────────────────────────────┐
│ 1. 直接匹配：是否为官方预设文件？      │──是──▶ 使用原值
└─────────────────────────────────────┘
    │ 否
    ▼
┌─────────────────────────────────────┐
│ 2. 继承链遍历：向上查找官方祖先        │──找到──▶ 替换为官方祖先ID + 填充nil
└─────────────────────────────────────┘
    │ 未找到
    ▼
┌─────────────────────────────────────┐
│ 3. 前缀匹配：最长官方前缀启发式匹配    │──找到──▶ 同上
└─────────────────────────────────────┘
    │ 未找到
    ▼
  错误: PRINTER_CUSTOM / PRINTER_NO_OFFICIAL_ANCESTOR
```

`--allow-custom-filament-presets` 和 `--allow-custom-printer-presets` 可放宽此限制。

### 3.4 重试机制

```
process_plate (最多 3 次)
    │
    ├── 尝试 1: 正常切片 + G-code 导出
    │   └── 成功 → 结束
    │   └── 失败 (append_tcr 错误) → 禁用 prime tower → 尝试 2
    │
    ├── 尝试 2: 重新切片 (无 prime tower)
    │   └── 成功 → 结束
    │   └── 失败 (append_tcr 错误) → 尝试 3
    │
    └── 尝试 3: 最后一次
        └── 仍失败 → EXIT_EXPORT_ERROR
```

### 3.5 几何检查（7 项）

全部作为 warning 收集，但任一检出即阻断切片：

| 检查项 | 方法 | 错误码 |
|--------|------|--------|
| 空网格 | `indices.empty()` | GEOM_EMPTY |
| 零体积 | `volume() < 1e-10` | GEOM_ZERO_VOLUME |
| 非流形 | `num_open_edges()` | GEOM_NON_MANIFOLD |
| 退化面 | `remove_degenerate_faces()` | GEOM_DEGENERATE |
| 自相交 | CGAL `does_self_intersect()` | GEOM_SELF_INTERSECT |
| 多组件 | `number_of_patches()` | GEOM_MULTI_COMPONENT |
| 法线反转 | `volume() < 0` | GEOM_INVERTED |

> Windows 上自相交检查使用 SEH `__try/__except` 包装，防止 CGAL 在病态网格上崩溃。

## 五、复杂度评分系统

### 5.1 设计理念

评分系统提供**两个正交维度**的评估：

| 维度 | 指标 | 作用 |
|------|------|------|
| 切片耗时 | score (1-20) | 队列调度、超时设置、用户体验 |
| OOM 风险 | memory_risk | Pod 规格选择、拒绝/降级决策 |

两个维度有相关性但不等价——高面片数宽扁模型可能 score=20 但 memory_risk=low，高层数细长模型可能 score 中等但 memory_risk=critical。

### 5.2 评分公式

```
score = S_curve(triangles) × config_multiplier × layer_factor

S_curve(x) = 1 + 19 / (1 + exp(-1.2 × (log10(x) - 5.7)))
  center = log10(500K) = 5.7, k = 1.2

config_multiplier:
  tree support ×1.6, normal support ×1.3, MMU ×1.2, ironing ×1.15, infill>25% ×1.1

layer_factor:
  1.0 (≤100 layers) ~ 1.6 (5000+ layers), sigmoid centered at 800 layers
```

### 5.3 内存风险评估

```
memory_index = estimated_layers × sqrt(total_triangles)

阈值 (基于 22 模型 k3s 验证, 2026-06-11):
  < 300K      → low      (16 GiB Pod 安全)
  < 750K      → medium   (16 GiB Pod 安全, 监控)
  < 1,500K    → high     (建议 32 GiB Pod)
  ≥ 1,500K    → critical (必须 32 GiB Pod, 可能仍 OOM)
```

### 5.4 调用方决策规则

```
1. Pod 规格（memory_risk）:
   low/medium  → 标准 16 GiB
   high        → 建议 32 GiB
   critical    → 必须 32 GiB, 若仍 OOM 标记不可切片

2. 超时设置（score）:
   trivial/normal →  60s
   moderate       → 180s
   long           → 300s
   extreme        → 600s

3. 队列优先级（score）:
   extreme 模型安排到空闲节点
```

### 5.5 3MF 解析流程

```
3MF 文件 (ZIP)
  ├── Metadata/project_settings.config  → 提取切片配置 (支撑/熨烫/填充)
  ├── Metadata/model_settings.config   → 提取对象名称
  └── 3D/3dmodel.model                 → SAX 解析
       ├── <resources> → 网格对象 (三角面片/顶点/AABB)
       ├── <build>     → 可打印对象列表
       └── <components> → 外部子文件引用（递归解析）
            ↓
       total_triangles, estimated_layers (= Z高度 / 0.2mm),
       bounding_box, object_count, shell_count
```

## 八、关键设计决策

1. **双入口设计** — 静态二进制 (`main.cpp`) 和共享库 (`main.c` → `slic3r_c_api.cpp`) 共享同一管线，C API 是 ABI 契约
2. **预设安全强制** — 默认所有用户预设替换为官方，防止 RCE 和非确定性输出
3. **防崩溃几何检查** — Windows 上自相交检查用 SEH 包装，防止 CGAL 在病态网格上触发访问违规
4. **进程隔离** — 每次调用创建独立临时目录（`orca_slice_<PID>_<timestamp>`），防止多容器碰撞
5. **JSON 始终输出** — 即使失败也输出结构化 JSON 和 `error_message`，方便调用方解析
6. **文件看门狗取消** — 云部署可通过创建指定文件来取消正在进行的切片
7. **推塔重试** — 最多 3 次重试，专门处理 wipe tower 工具更换不匹配（CGAL 跨平台浮点差异）
8. **日志级别作用域** — `ScopedLogLevel` 在加载/切片/导出等已知高噪声阶段抑制 logs3r 详细日志

## 九、已知问题与风险

| 类别 | 问题 | 影响 |
|------|------|------|
| **OOM** | G-code 导出阶段引擎全量保留板 G-code 数据直到写入完成，高面片+高层数组合可导致 >15 GiB 内存占用 | 醒狮眼镜仔系列在 16 GiB Pod 上 OOM，32 GiB 下待验证 |
| **评分精度** | `memory_index = layers × sqrt(triangles)` 无法完美预测 OOM，醒狮眼镜仔(6) index 低于中式楼阁却 OOM | 存在 false positive 和 false negative |
| **文件大小上限** | 默认 `--max-size 200` MB，大文件需手动设为 0 | 214 MB 模型需显式指定 |
| **自定义耗材** | 默认拒绝自定义耗材预设，需 `--allow-custom-filament-presets` | 用户克隆改名后继承链断裂 |
| **Windows 打包** | tar 不保留 Unix 权限，需 `chmod +x` 修复 | 部署时多一步操作 |

## 十、后续优化计划

### P0 — 紧急

| 序号 | 项目 | 说明 | 预期效果 |
|------|------|------|----------|
| 1 | **流式 G-code 导出** | 引擎侧边写 `.gcode.3mf` 边释放内存，避免全量累积。需要修改 libslic3r 的 `Print::export_gcode()` 流程，将当前"全生成→全写入"改为"逐层生成→逐层写入→立即释放" | 醒狮眼镜仔系列可在 16 GiB Pod 完成切片，内存峰值预计从 15 GiB 降至 2-3 GiB |
| 2 | **G-code 导出内存预估** | 在复杂度评分中增加基于实际 toolpath 密度的内存预估，替代当前的 `layers × sqrt(triangles)` 简化模型 | 提升 memory_risk 预测精度，减少 false positive/negative |

### P1 — 高优先级

| 序号 | 项目 | 说明 | 预期效果 |
|------|------|------|----------|
| 3 | **大内存 Pod 验证** | 对 mem_risk=critical 模型在 32 GiB Pod 上重新切片，确认醒狮眼镜仔全系列是否能在 32 GiB 下完成 | 确定真正的"不可切片"阈值 |
| 4 | **评分系统集成到 C API** | 将 Python 评分逻辑内嵌到引擎中（C++ 实现或嵌入 Python），`slic3r_slice()` 返回评分结果作为切片前置检查 | 减少跨进程调用，延迟降低 |
| 5 | **自定义耗材默认宽容** | 将 `--allow-custom-filament-presets` 改为默认启用，仅对完全无效的耗材拒绝 | 减少用户因继承链断裂导致的拒绝率 |
| 6 | **多层板并行切片** | 当前逐板串行处理，多板模型可并行启动多个 Print 对象 | 多板模型切片耗时降低 50-70% |

### P2 — 中优先级

| 序号 | 项目 | 说明 | 预期效果 |
|------|------|------|----------|
| 7 | **切片进度回调增强** | 当前仅输出 `[Progress] N%` 文本，增加结构化 JSON 进度事件流（含阶段、预估剩余时间） | 云服务可实时展示进度，用户体验提升 |
| 8 | **3MF 预检缓存** | 对同一 3MF 文件的几何检查和配置验证结果缓存（基于 SHA256），避免重复检查 | 重复切片同一模型时跳过验证，启动延迟降低 50% |
| 9 | **增量 G-code 输出** | 支持切片过程中逐层流式输出 G-code（而非等待全部完成），配合 WebSocket 推送给客户端 | 适合大模型长时间切片的交互场景 |
| 10 | **G-code 压缩传输** | gcode.3mf 内置的 G-code 文件使用 zstd 压缩后再打包 | 输出文件体积减小 60-80%，上传/下载更快 |

### P3 — 低优先级

| 序号 | 项目 | 说明 |
|------|------|------|
| 11 | **引擎热更新** | 支持不中断服务的引擎版本切换（双版本并存，新请求路由到新版本） |
| 12 | **切片统计面板** | 基于 JSON 统计输出构建 Prometheus metrics，可视化切片成功率、耗时分布、OOM 率 |
| 13 | **自动重试分级** | 根据失败类型自动决定是否重试（OOM 不重试，网络瞬断重试），替代当前固定的 3 次重试 |
| 14 | **多机型支持** | 当前仅支持 Snapmaker U1，扩展到 J1、Artisan、Ray 等机型 |
